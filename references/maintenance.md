## 7. RAG 检索与引文核验（2026-09-22 增）

**`tools/rag.py`**——把"检索"与"防瞎编"合成一步。**零索引文件、无需重建**（每次实时扫描 `data/`，约 1–3 s/次）。四个子命令：`query`（默认）｜`verify`｜`stat`｜`selftest`。规则位在 `SKILL.md` 铁律 1、8 与「检索入口」节。

改它时要知道的几件事：

- **为什么不用向量模型**：文言正史里人名（張居正/张居正）、年号、异体字做嵌入会漂移，且**无法保证逐字引文**——而正史要求逐字照录。所以召回唯一依据是**精确子串匹配**，靠 `RAG_VARIANTS` ＋ `tools/aliases.md` ＋ zhconv 繁简扩展兜召回。
- **两级检索**：① 文件级 `bytes in` 过滤并顺带统计 df（算 IDF）② 只对候选文件解码切段打分。改 `retrieve()` 的打分项时，注意 `cover*1000` 是主序（关键词覆盖优先），`[原文]` 有 +120、`[待核]` 有 −40，字数有 −0.25/字 的紧凑度惩罚。
- **原文/译文判定**（`file_mode`／`chunks_labeled`）是**依内容**判的，不依 `> ` 符号：五种模式 `normal`／`alt`／`all_orig`／`tzj`（通鉴补入卷 `译：` 行）／`marker`（宋史等 `**【原文】**` 显式标记）。判据是文言虚字（之于者也）/白话字（的了这那）密度的中位数之差。**改 `BAI_CHARS`／`WEN_CHARS`／`chunks_of` 的断段规则后，务必跑 `rag.py selftest`**——那里有 06宋书、20宋史、01史记 三个样本的断言兜底。
- **段必须按"引用块/明文交界"断开**：文白对照卷的原文与译文常相邻无空行，不断开会把文言与白话混进同一段，导致判定与引用全错。
- **机读稿恒判 `[OCR稿]`**，索引文件恒判 `[索引]`——都不是原文，不允许被引用。
- **异体字/人名异写**往 `RAG_VARIANTS` 加一行（`｜` 分隔同组，如 `努尔哈赤|努尔哈齊|努尔哈齐`）；**人物异文**仍写 `tools/aliases.md`（02 索引与 rag 共用）。
- **`verify` 的四类判据**：查无此文（≥8 字即 FAIL）、书名错配（引文实际出自 A 却注成 B）、卷号不存在（`juan_exists`）、引白话译文当原文（WARN）。它先在**被引书文件夹内**查（快且准），未中才全库查。加新判据就往 `cmd_verify` 里加一段，保持 FAIL/WARN/OK 三级与退出码 1 的约定。
- **性能（2026-09-22 二轮）**：① `expand_terms` 里的 `tools/aliases.md` **只在启动时读一次**（`_ALIAS_GROUPS`）——原先段级循环里每调一次就读一次盘，实测 20宋史文白 的 13581 段＝13581 次读盘＋zhconv；② `retrieve()` 对每个**原始词**只展开一次变体（`_TV`），原先 4 处调用点里 2 处在逐段循环体内重算。改 `expand_terms`／`retrieve` 后必跑 `rag.py selftest`。
- **`locate` 子命令（2026-09-22 二轮）**：原 `tools/q.py` 并入为 `rag.py locate`（`q.py` 留作转发薄壳，删它前先改掉 SKILL.md／selftest.py 里的引用）。q.py 原先自带的 `variants()` 只做 zhconv、**不读 `tools/aliases.md`**，与 `rag.py` 召回不一致——现已统一走 `expand_terms`。`_loc_hit_lines` 改为「未命中行不解码」（原先每行先 decode 再判命中）。
- **繁简互通有体检了（2026-09-22 二轮）**：`selftest.py` 现在断言「查简体『张居正』必须同时命中简体＋繁体机读稿」——繁体命中只能靠 zhconv 转出「張居正」。原先 q.py 冒烟样本用「魏徵」（该写法本就在 02 索引里），**zhconv 缺失也照样通过**，而缺了它是静默降级。

改这三处时要守住的点：

- **`tools/aliases_events.md` 的右端词必须是实测存在的词**（`python tools\rag.py <词> --count`）。右端写了个库里也没有的词 = 换个姿势再零命中一次。已实测无载者记在文件头部"已知本库无载"行（如 苗刘、释兵权、北狩、二帝）。**右端可不写"超串已测词"的验证**：已测「禄山」则可写「安禄山」，超串命中必蕴含子串命中。
- **篇名行探测只在"传/纪类、且带 `# ` 卷题标题"的文件上生效**（`head_i` 判据）：通鉴等无标题书首行是编年题（「晉紀三十二」），志/表类（卷题含志/表）一律不参与。**只认紧邻卷题的第一个短行**——早期版本取了"首个短行到第 6 个短行之间的区间"，结果把本纪/表的正文首段圈进区间、整段误标成本传（宋史卷 42、卷 215 实测踩过）。改这块务必跑 `rag.py selftest`，里面锁了「苏轼 → 宋史 338 本传置顶」这条断言。

### 17. `description` 精简：只留触发面，规则一律回正文（2026-09-24 用户："精简 skill 描述，可以没有提速，但一定不降质量"）

`description` 是**每次会话常驻**的那一段（正文只在 skill 被触发后才加载），旧版 898 字里塞满了
抽签公式、取号凭证、志表禁令、石勒／拓跋珪反例这类**程序性细则**——它们与正文重复，却常年占着上下文。
现压到 **527 字**：只保留 ①库是什么／多大规模 ②"先跑 `rag.py` 再答，禁止凭记忆" ③能力清单
④触发词表（`selftest` 要求 宰辅年表／年表／世系表／字什么／讲个历史故事／OCR辅助稿 六词必须在）
⑤讲史与猜谜两条入口的一句话裁决 ⑥「读不到选签表就明说」。
**收益是常驻变短，不是检索变快——提速本就不是目标，质量不掉才是验收线**，故逐条做了防退化：

- **删前核对**：每个被删子句先确认正文有等价条文（`(L mod 27)+1`／「选签 第 k 条」凭证／**禁止惯性连带**／
  **虚构必标注**／**独有引语反查**／石勒·拓跋珪反例），核对口径已固化成下面的闸。
- **正文补两处**：① 讲史**禁讲志／表类制度记述**原先**只活在 description**，已搬进「硬规则」首条
  （并说明 `04`／选签表在建库时已剔除志表卷，零工具环境自选篇目须先确认卷题是列传／本纪）；
  ② 「读不到选签表必须明说、不得编一个故事充数」正文侧原先**也没有**，已写进 1-alt-2 末。
  顺带把「**五条**硬规则」这个数不对的小标题改成「硬规则」（实际 9 条）。
- **`selftest` 加 `BODY_RULES` 闸**（7 条关键词，缺一即 FAIL）：把这次"删前逐条核对"变成回归——
  以后任何人再精简 `description`，只要正文里对应规则不见了就会被拦下，而不是等某次讲史翻车才发现。
- ⚠ 该闸用 `split('---', 2)[-1]` 取正文（frontmatter 只有两处 `---`，正文内无），**别改成行号切片**——行号会随正文增删漂移。

**精简后紧接着炸出的一次误用（2026-09-24 用户第三张截图）**：某**只加载 description、跑不了命令**的环境收到六道线索的
「猜皇帝」，回答只有一句 **「我读不到选签表」**。根因不是精简，而是那句逃生阀**从一开始就写在 description 里、
却没限定场景**——它本是"讲史取不到号"的专用免责语，人物题借用它＝答非所问，且比硬猜更隐蔽（看起来像守规矩）。
修法：① description 里该句必须**贴着讲史限定语**出现（「只有讲史请求才可能说这句」）；② 另给人物题适用的降级口径
「本环境跑不了检索 ⇒ 答『我查不到原文库，无法确定』＋原因，严禁凭记忆猜人」，并升为**铁律 10**；
③ `selftest` 加两道闸：`读不到选签表` 前后 ±60 字内没有「讲史／故事」即 FAIL、description 缺「我查不到原文库」即 FAIL，
`BODY_RULES` 同步补两条（降级口径＋"不得搬到人物题"必须在正文）。触发词补「猜皇帝」「这是谁」——这类题面
原先只能靠"特征辨识"四字命中。**description 608 字**（仍比旧版 898 短 32%），`selftest` 全绿。
教训：**逃生阀式的短句（"那就明说 X"）在 description 里等同于全局指令**——常驻段里每一句"可以这样推脱"
都必须写明适用场景，否则模型会挑最近的一条来交差。

### 18.1 `verify` 的用法要点：一条引文一行、出处同行（否则假 FAIL）

初稿把同段多条引文写在一个句子里（`《通鉴·卷77》行245：「A。」同条接叙「B。」末云「C。」`），
随后另起一行给下一本书的出处——`verify` 的 pre/post 书名窗口把**邻行的《晋书》当成了 C 的出处**，
一次报出 5 条「书名错配」（正是"宋书／宋史"式翻车的样子）。**正确写法**：每条引文独占一行、
出处与引文同行、行首用 `- `（post 窗口在下一个列表项处截断）。改后 FAIL 5 → 0。

另：引文**必须逐字照录**，不得在引号内加 `**` 加粗、不得把原文的 `“ ”` 换成 `『 』`——
初稿这样做，`verify` 一次报出 16 条「长引文查无此文＝疑似编造」。加粗请加在引号**外**。
